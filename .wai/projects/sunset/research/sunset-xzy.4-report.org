** Pinned semantics recorded (module docstring + code)

- Comparison surface (D4): simplified source only — grayscale decode, ink
  iff gray strictly below recorded threshold, dilated per recorded
  =ink-dilation-<N>px= (8-connected, same parser semantics as coverage.py).
  =none=/unparseable -> unknown =source-simplification-missing=; disabled/
  non-pinned binarization -> unknown =binarization-not-configured=;
  undecodable bytes -> unknown =render-decode-failed=; missing/unmapped
  frame -> unknown with the frame reason.
- Exact region rule: ink agrees iff min <= measured <= max; no-ink agrees
  iff measured <= min (floor = complement bound; min <= max makes it
  trivially <= max). Mirrors coverage.py's pinned per-region semantics.
- ink-outside-rect (pinned refinement, verdict STAYS differ): fires only on
  a failing "ink" claim whose rect has no RAW ink while the raw mask has
  ink within the recorded dilation N px (Chebyshev) outside the boundary —
  misplaced, not missing. The oracle never elects to move/grow the region;
  the reason is attribution only ("No silent resolution"). Single threshold
  = the recorded dilation; a blank-neighbourhood control proves missing ink
  stays a plain differ.
- Page agrees iff every region agrees (region-scoped: deliberately NO
  whole-page fraction requirement); empty claims + usable calibration =
  documented vacuous agree. Malformed/out-of-bounds/vocabulary-violating
  claims are retained differs.
- Aggregate = shared rule via coverage.aggregate: pass only if every page
  agrees (agree implies usable recorded calibration); unknown/unavailable/
  differ/empty -> blocked + reasons.

** Deviations

1. RED failure class ImportError vs ModuleNotFoundError — same gate, noted
   above.
2. Test-geometry correction during GREEN (test-only fix, implementation was
   already correct): REGION_MISPLACED first placed at descriptor x 401..403
   and hand-measured as 0.5 dilated. Reality: pymupdf draw_rect with
   color+fill strokes the boundary (1pt stroke straddles it by 0.5pt), so
   raw ink reaches raster col 400 and the 2px dilation reaches col 402 —
   the rect measured 1.0 and agreed under min 0.9. Moved the rect to
   x 402..404 (measured 0.5, differ) with the raw ring [400,402) still
   inked, so the attribution control is honest. Diagnosed by measuring the
   actual mask bbox (exactly x 100..400, y 192..492); an intermediate
   column probe had used height as the row stride and produced bogus
   numbers — bbox measurement settled it.
3. masks.aggregate delegates to coverage.aggregate (identical pinned rule,
   duck-typed over outcomes) rather than duplicating it; masks adds only
   its own docstring. AlignmentOutcome/AggregateOutcome/PROPERTY stay
   module-local; the calibration validator is masks-owned because it must
   bind property="region-alignment" (coverage's validator binds
   "ink-coverage" and was therefore NOT reused).

** Findings (for the lead / future slices)

1. pymupdf draw_rect(color=..., fill=...) STROKES by default: raw ink
   extends 0.5pt beyond the fill rect on every side. xzy.3's "rects
   integer-exact" note holds for the fill but the stroke adds a 1px halo at
   72dpi. Any future hand-computed fixture that places a rect ADJACENT to
   an ink block must budget for this +1px halo (or draw fill-only via
   draw_rect(rect, fill=..., color=None, width=0)). Worth folding into the
   mutation-fixture work (5.1) where seeded shifts will be sized in pixels.
2. The ink-outside-rect refinement is reconcilable with D4 and shipped as
   attribution-only: dilation bleed within N px can lift a displaced region
   to agree through the normal calibration path (that IS the D4 tolerance);
   the reason only fires when the primary test fails anyway. No spec-level
   ambiguity requiring the follow-up threshold — no STOP.
3. Reusing coverage.py private helpers by import worked cleanly and kept
   the two oracles' parsing/dilation/rect semantics literally identical;
   if a third oracle repeats the pattern, consider promoting those helpers
   to a shared private module (not done here — out of scope, no edits to
   coverage.py allowed).
