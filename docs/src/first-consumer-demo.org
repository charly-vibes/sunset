## Pinned configuration (recorded 2026-10-15)

- Extractor B: PyMuPDF 1.28.2 (page.get_text)
- Adapters: dsc03.adapters (sunset-carrier 0.1), inventory/manifest pinned

- Readers: dsc03.canonical reader_a/reader_b (byte-identical output)
- Labels: dsc03.conformance.classify

## Workflow (once the issue exists)

1. [HITL] Two independent human reviewers annotate the issue BEFORE seeing any
   extraction output; disagreements retained (not resolved).
2. Run both extractors; adapt each output through dsc03.adapters into a 0.3
   descriptor snapshot (one adapter run per extractor, separate snapshots).
3. Read both snapshots through reader_a/reader_b; assert canonical byte
   agreement per snapshot.
4. Compare extractor outputs via dsc03.projection against the reviewers'
   expectations (oracle: required + allowed_unresolved + forbidden).
5. Separate reviewing consumer: human reviewer performs the review task list
   below twice — once on DSC output, once on native extractor output —
   measuring time, correct decisions, descriptor bytes, peak memory.

## Reviewer task list template (fill per issue)

| # | Task | Source fragment | Decision |
|---|------|-----------------|----------|
| R1 | Verify heading text of lead article | page:N | correct/incorrect |
| R2 | Trace a continuation sentence across pages | page:N->M | correct/incorrect |

| R5 | Confirm the unsupported feature is declared, not hidden | coverage | correct/incorrect |

- Reference set (reviewers' annotations) exists BEFORE extractor evaluation
- Nonempty set of resolvable observations + separately listed allowed
  unresolved cases; zero incorrect anchors may be marked verified

- No demo/baseline -> workflow benefit stays "unproven" (dsc03.conformance)
