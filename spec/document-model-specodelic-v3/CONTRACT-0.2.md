# DSC 0.2 JSON contract (normative for this prototype)

This contract intentionally limits the wire format. Its JSON keys and core relation meanings are normative; PDF/EPUB adapter internals are not. Every top-level field below is mandatory, arrays may be empty. Unknown fields and nulls are prohibited. UTF-8, NFC strings, ASCII field names and IDs; no floats, NaN, infinities or duplicate JSON keys. Canonical bytes are Python `json.dumps(sort_keys=True, ensure_ascii=False, separators=(",",":"))` encoded UTF-8 after NFC checks; no trailing newline. This is a deliberately restricted canonical JSON profile, **not** a claim of complete RFC 8785 compliance.

```
{"version":"0.2","id":"issue-1","source":{"format":"pdf","sha256":"<64 lower hex>","locator":"local:issue-1"},"regions":[],"contents":[],"relations":[],"annotations":[],"evidence":[],"vocabularies":[]}
```

- **source** exactly `format` (nonempty lower-case term), `sha256` (64 lowercase hexadecimal characters), `locator` (stable reference within a snapshot; must not be used as identity). A placeholder digest is forbidden.
- **regions** objects exactly `id`, `view` (`physical|logical`), `kind` (nonempty string), `geometry` (optional). Geometry exactly `space` (nonempty string, e.g. `pdf-page-1-pt`), `x`, `y`, `width`, `height` (nonnegative integers). `width=0` is permitted, meaning degenerate geometry, not invisible text. Rotated/mirrored geometry can be described by a named source coordinate frame; actual affine matrices remain adapter extension work.
- **contents** objects exactly `id`, `kind` (`text|image|number|structured|binary-reference`), `value` (string). Format-native binary content is represented by a reference, never embedded bytes. Text retains line breaks. Different regions may point to the same content instance.
- **relations** objects exactly `id`, `kind` (`contains|precedes|realizes|has-content|derived-from`), `from`, `to`. `contains` region→region, `precedes` region→region, `realizes` physical-region→logical-region, `has-content` region→content, `derived-from` evidence→evidence. A region other than the document root must have exactly one incoming `contains`; `precedes` and `derived-from` must be DAGs. For a document with multiple physical page roots, create a logical root and use `contains` to attach each page. The root is the unique region with no parent. `precedes` edges are generators of a partial order by reachability, not its full transitive closure. No implicit reading order.
- **annotations** objects exactly `id`, `target` (region/content ID), `term` (`namespace:term`), `value` (string), `origin` (`source|extracted|inferred|manual|external`), `status` (`supported|disputed|asserted_without_evidence`), `evidence` (array of evidence IDs). `supported` must have at least one evidence ID; `asserted_without_evidence` must have none. `disputed` can retain any number of evidence IDs. Contradictions are retained as distinct annotations; this prototype validates declaration, not logical contradiction detection.
- **evidence** objects exactly `id`, `origin` (same origin vocabulary), `source_ref` (nonempty), `transform` (optional). `transform` is exactly `id`, `version`, `config_sha256`, `dependencies` (array of strings); derived observations need this record. `source_ref` refers to source coordinates, fragment identifiers or a source digest. It is an opaque locator, not an automatic proof of truth.
- **vocabularies** objects exactly `namespace` and `version` (nonempty strings). Core terms are built in. Extension terms must use one declared namespace. `version` pins its semantics per descriptor. The example `demo@1` is only a fixture.

**Identity:** IDs are unique *across all five instance arrays*, not only per array. They are stable only within the immutable descriptor snapshot and its canonical reserialization. Re-extraction may allocate new IDs; cross-snapshot linkage requires extension mappings.

**Interpretation outcomes:** malformed input / broken relationships → `invalid` with sorted reason codes; supported descriptor → `valid`. Carrier adapter outcomes additionally support `unsupported` and `ambiguous`. These are not guessed from schema validity.

**Exclusions:** source-native PDF glyph geometry, EPUB nav trees, per-region observations, language direction, CSS visibility, multi-edition semantic projections and independent reader agreement need adapter/vocabulary extensions. Descriptors can carry evidence and structural groupings, but this JSON profile does not claim lossless encoding of every carrier. Future additions require a new version or explicitly registered namespace; unknown keys fail closed.
