## Test shape before implementation

Inputs: immutable PDF bytes; page/render and crop profiles; pinned pipeline policy; recorded or local provider outputs; limits. Outputs: immutable run manifest, region/content/structure revisions, DSC descriptors, unresolved diagnostics, resource ledger and replay report.

First executable fixtures must include: a mixed-column page requiring a split; a poem whose line/stanza breaks survive recognition; an image/caption pair; a cross-page continuation; a repeated proposal causing a cycle; malformed AI output; a changed model/config causing cache invalidation; missing replay artifacts; and a budget exhausted before another call. Stubbed provider responses make orchestration tests reproducible without paid inference. Real OCR/AI evaluation is separate.

## Invocation and inspection contract

The first slice exposes a local headless interface with four operations: run(source path, selected page numbers, configuration path, new output directory), resume(run directory), replay(run directory, new output directory), and inspect(run directory). The planned public syntax is `python3 -m digitization run --source PDF --pages 2 --config CONFIG --output NEW_DIR`, `python3 -m digitization resume --run RUN_DIR`, `python3 -m digitization replay --run RUN_DIR --output NEW_DIR`, and `python3 -m digitization inspect --run RUN_DIR`. These commands are not implemented today; task 1.1 must document working examples. Resume support is completed by task 2.2, replay by 2.3; temporary unsupported diagnostics in 1.1 cannot satisfy those later checkpoints. No browser or network service is required. Page numbers are one-based PDF page indices, not printed labels. Invalid selection/configuration or a nonempty new output directory is refused before inference and without overwriting artifacts.

Run/resume returns a manifest path and status. The run directory contains the pinned source/configuration, hash-addressed artifacts, revision graph, selected DSC descriptors, UTF-8 searchable text with page/region source mappings, unresolved coverage report, append-only decision trace and durable resource ledger. Inspect produces a local human-readable summary of regions, raw/layout/search text, alternatives, source selectors, revision lineage, stop reason and usage, plus a machine-readable report referencing the same digests. A reviewer can identify an omitted region and follow a selected text span back to its PDF page/frame without Lens. Replay writes its verification report and reconstructed semantic outputs separately, leaving the original evidence untouched.

Result statuses distinguish completed execution, stopped with unresolved work, invalid input, and replay failure; diagnostics carry stable reason codes. Completed execution means the configured checks passed, not verified transcription correctness. A smoke fixture pins page 2, a poem region, one unresolved caption and expected text/source mappings; an invalid page and missing configuration produce no provider calls.

## Architecture and decisions

1. Pin source bytes and render pages with recorded renderer/version, DPI, rotation and pixel-to-source transforms. Treat page images as source evidence and region classifications as proposals. Do not require OCR to discover initial regions.
2. Detect provisional regions, then recognize text per region using a configured route. A deterministic layout tool may propose initial geometry; image-model proposals are also allowed and recorded. No engine/provider is mandated until the pilot measures alternatives.
3. Propose structure using recognized text AND source images/layout. Articles, titles, authors, poems, captions and continuations remain attributed hypotheses; reading order can be partial. Preserve line breaks, stanza separation, indentation and their source geometry separately from normalized search text.
4. Evaluate a versioned policy of checks: out-of-frame/clipped regions, missing coverage, duplicate observations, order conflicts, suspicious text and broken continuation links. Each rule defines its inputs, thresholds, severity and candidate actions; confidence is tool-specific and is not a correctness oracle. Human judgments are separate evidence.
5. Apply explicit actions (split, merge, expand, rerecognize, restructure or escalate). Sort pending actions by pinned priority, page, canonical semantic region label, rule ID and canonical action digest (with allocation IDs replaced by semantic labels). Validate proposals before admission. Recompute the affected dependency closure, including neighboring-page links, and reuse unrelated artifacts.
6. Stop on satisfied configured checks, no new canonical state, repeated state, exhausted limits or unrecoverable provider failure. Preserve the last valid state and unresolved diagnostics; do not label a budget stop complete. Fixed point means stable under the configured policy, not correct transcription.

### Semantic state equality and cycle detection

Cycle detection uses a separate versioned semantic projection, not revision hashes. Under a pinned source/configuration it includes the multiset of active region records (source page, frame, exact geometry, role hypotheses and attribution), selected raw/layout/search content, unresolved alternatives, coverage/check outcomes and structural relationships. Local object/revision references are replaced by canonical graph labels: choose the lexicographically least canonical JSON encoding over bijections preserving node kinds, attributes, edge labels/direction and multiplicity. Equal geometry never merges nodes. This definition is independent of allocation IDs; implementation may optimize only while preserving these bytes. Geometry uses exact canonical numbers under the pinned transform profile, without implicit tolerance. Attribution retains producer/configuration and manual-observation identity, but excludes execution attempt IDs and response-envelope digests. Raw provider artifacts remain retained outside the projection.

Exclude revision IDs, parent/history edges, timestamps, iteration counters, run/attempt IDs, usage and billing. Pending actions are deterministically derived from this projection and pinned policy; hidden scheduler state is forbidden. Store projection bytes and digest for the initial and every admitted state; verify bytes on a digest match. An immediate repeat is stable-state; a nonadjacent repeat is repeated-state. Thus A→B→A with newly allocated revision IDs stops as repeated-state, retaining all three revisions. A→B→C with a changed raw poem newline, alternative, attribution or relation is not a repeat. This equality is only for orchestration; it does not redefine DSC identity or evidence equivalence.

### Artifact identity and replay

Use versioned canonical JSON and SHA256 for structured identities. An operation key binds operation/schema version, ordered input digests, page/crop transforms, implementation/dependency versions, model identity (including whether the remote revision is unavailable), prompt/schema digest, language, preprocessing, decoding options and policy configuration. A hit requires verified output bytes and a valid artifact. Fresh inference is explicit and creates another attempt; the cache never silently substitutes a new output for the selected one. Concurrent attempts preserve all outputs, while the manifest pins the selected digest.

Record raw responses, validated normalized outputs, tool errors, usage and explicit selection. Append revisions with parent revision IDs and split/merge mappings; geometry is not identity. Link pipeline metadata through a sidecar manifest to valid DSC objects rather than adding unapproved wire fields. Do not claim existing text-range evidence replay supports image-to-text inference: pipeline recorded replay verifies artifacts and reconstructs decisions; fresh OCR execution is a separate verification mode.

Replay requires all referenced artifacts and checks their hashes. Reconstruct canonical semantic outputs and decision trace with no inference or network. Timing, timestamps, usage and billing observations remain in an execution envelope outside semantic byte comparisons; they are retained and integrity checked, not fabricated. Missing artifacts yield incomplete replay, corrupted artifacts fail integrity, unsupported versions yield unsupported replay.

### Budgets and failures

A versioned run configuration pins nonnegative integer limits for page refinement rounds, total provider attempts and estimated monetary cost in integer micro-units of a declared currency; it also pins request input/output bounds and a price schedule digest. Reserve a conservative upper-bound cost before dispatch, settle from usage and retain failed-call charges. Retry attempts consume limits. If a provider cannot bound cost, disable it under a hard monetary cap. Record local compute time separately; estimated provider cost is not an invoice or total operating cost. Check limits before dispatch; resume uses the existing ledger rather than resetting spend.

Reservations and dispatch intentions are durably recorded atomically with attempt consumption before sending a request. An attempt has a unique request key and states reserved, dispatch-uncertain, completed/charged-failed, or confirmed-not-dispatched. Persist dispatch-uncertain before network I/O; a crash anywhere afterward keeps the entire reservation encumbered. Available allowance equals cap minus settled charges minus outstanding reservations. Restart never releases a reservation merely because no response exists.

Resume first reconciles uncertain requests through provider status/usage lookup or a documented idempotency guarantee binding the same key and payload to one execution/charge. Persist receipts and settle each attempt once. An idempotent retransmission uses the original reservation/key and records transport retries; a new inference attempt needs a new key, reservation and attempt allowance. Without reconciliation or guaranteed idempotency, do not automatically redispatch: retain the maximum charge and report dispatch-uncertain for explicit resolution. Only evidence of non-dispatch permits refunding that reservation; confirmed charged failures remain charged. Duplicate receipts cannot settle twice. Local adapters obey the same durable attempt rules, even with zero monetary charge. Task 2.2 must wire the public resume invocation: terminate a subprocess after durable reservation/dispatch intention, start a fresh process with `python3 -m digitization resume --run RUN_DIR`, and verify original manifest identity, history, selected artifacts and ledger continuity. No new run directory, reset attempt count or duplicate dispatch/settlement is permitted. A provider without lookup/idempotency must return stopped-with-unresolved-work / dispatch-uncertain and make zero replacement calls; missing run directories are invalid-input, never new runs.

### Bounded local-provider integration

Task 2.4 owns a real local vertical slice before either measured pilot: public run → page render → image-based region detection (no OCR prerequisite) → actual crop OCR → attributed DSC and text → public inspect, plus whole-page OCR baseline mode using the same pinned engine. Select and approve the installed local engine/configuration in the difficult-page configuration gate before the real smoke run. Reuse/adapt the rendering/Tesseract paths in `dsc03/demo.py` and `dsc03/substrate/oracles.py` where appropriate; document reuse decisions and avoid calling the whole-corpus demo for a crop. Preserve raw OCR bytes and layout rather than inheriting stripping/word-joining behavior that loses poem spacing. No unrelated refactoring of those modules is required.

Deterministic fake subprocess tests must prove real adapter wiring, requested crops/transforms, engine arguments, failure handling and source mappings; fakes alone cannot close the slice. Also retain one separately invoked bounded real local smoke run on the approved difficult page, with source/configuration/renderer/engine/traineddata digests or versions, argv, actual attempts/runtime, ledger, descriptor validation and inspect output. Missing executables/language data or a nonzero/timeout engine exit yields explicit provider-failure with diagnostics and no fabricated empty success. Smoke outcomes establish integration, not accuracy. Real inference is excluded from default tests; all external routes stay disabled. An explicitly approved engineering configuration may omit references, but its smoke/evaluation remains evaluation-incomplete and cannot pass quality/economy gates.

### Relationship to current proposals

DSC deployed requirements remain authoritative. Pending composition semantics inform explicit split/merge lineage, views and continuations but are not assumed deployed. Lens is an optional review consumer; this proposal does not amend its no-implicit-OCR boundary. The digitizer explicitly produces attributed outputs which Lens may load. A representation gap must become a minimized witness and separate core change, not an invented extension.

## Evaluation and rollout

Before each stage's inference, freeze its own local experiment manifest selecting pages, baseline whole-page OCR configuration, routing/refinement policy, limits and evaluation rules. The difficult-page stage uses `fixtures/digitization/pilot.json` and `reference.json`; the six-page stage uses `six-page-pilot.json` and `six-page-reference.json`. Retain the earlier stage unchanged. Difficult-page approval does not require six-page references. After the difficult-page assessment, a separate six-page reference/configuration approval blocks six-page inference, not the first experiment. Reuse source-linked human sheets only within their recorded scope; they are not transcription gold or automatic identity mappings. Establish independent reviewed reference text/regions for the evaluated subset or report those quality metrics unknown.

Report region matching under a pinned overlap/mapping policy; character error rate with declared Unicode/whitespace handling; line/stanza/indentation preservation; explicit reading-order/continuation errors; unexamined coverage; actual calls/cache hits/estimated charges/runtime; and timed correction effort when measured. Preserve raw text even if evaluation normalizes it. Compare baseline and loop on identical pages. Include at least two uncached runs on the difficult page to measure fresh-run variation and a no-inference replay comparison. Report setup/reference effort separately and all unsuccessful runs. No cost or quality winner is preselected; publish acceptance or rejection of scaling based on the evidence.

### Reproducible evaluation operation

Task 3.1 owns `python3 -m digitization evaluate --baseline BASELINE_RUN --candidate CANDIDATE_RUN --reference REFERENCE_JSON --policy STAGE_MANIFEST --output NEW_REPORT_DIR`. It performs no inference/network calls and emits machine-readable metrics plus a human-readable report, bound to all input/configuration/output digests. Tasks 3.2 and 3.3 must invoke this same operation, retaining argv, exit status and reports. A pinned policy defines Unicode/whitespace normalization, one-to-one region matching and tie order, overlap threshold, exclusions and text/line/stanza/indentation/order/continuation units. Report numerators, denominators, missing/spurious items and witnesses separately, including unmatched/unexamined reference units; never score only successful candidate matches. Runtime/calls/cache/charges come from verified ledgers, not new inference. Unknown correction/setup effort stays UNKNOWN.

Before implementation, pin these known-answer fixtures in `tests/tracer/test_digitization_evaluation.py`:

- Identity Unicode normalization, no whitespace folding; reference `ab`, baseline `ac`, candidate `ab`: baseline one substitution / two reference characters = CER 0.5; candidate 0/2 = 0. Missing text reference or zero eligible reference characters gives UNKNOWN/evaluation-incomplete, never 0.
- One-to-one maximum-total-IoU matching, threshold 0.5 inclusive, ties by canonical source geometry then stable recorded IDs: two reference boxes, two candidate boxes, exactly one identical pair and all other overlaps zero gives one match, one missed and one spurious region; precision 1/2 and recall 1/2. An extra candidate competing for the same reference cannot create a second match.
- Two reviewed line-break boundaries, one retained, gives one missing / two boundaries = 0.5 boundary error. Include separate stanza/indentation fixtures and preserve their denominators; do not substitute normalized search text for layout evidence.
- Two reviewed directed continuation edges, one correct and one replaced by a wrong endpoint: one matched, one missing and one spurious, reference denominator 2; report missing 1/2 and spurious count 1 with endpoint witnesses. Add a reversed reading-order edge fixture with the same explicit accounting. Do not infer relationship identity from equal geometry.
- A missing page/reference scope or empty denominator blocks positive quality/economy/scaling conclusions even when every scored unit passes. Engineering output is evaluation-incomplete; failed/excluded units and unknown measures remain visible. A complete reference with a threshold failure produces a measured rejection, not UNKNOWN.

These fixture values validate the evaluator, not preset pilot success thresholds. Stage thresholds and any alternative matching/normalization policy must be frozen with known-answer coverage before that stage's candidate inference.

### Minimum evidence for a pilot decision

Before scoring the difficult page, freeze an independently reviewed, source-digested reference covering that entire page: all regions and coverage dispositions, verbatim text, at least one poem with line/stanza/indentation geometry, an image/caption relationship and scoped reading order. If the selected page lacks one of these features, the manifest must select and review an additional excerpt page containing it before a combined quality/economy claim. For the six-page decision, require reviewed region/coverage and text/layout references for all six pages plus at least one reviewed cross-page continuation pair with both endpoints; disputed items stay explicit and are excluded with counts and reasons. References record reviewer identity, scope, digest and approval independently of candidate outputs; human sheets cover only judgments they actually contain.

The manifest pins nonempty eligible reference units, metric denominators, exclusions, numerical quality thresholds and cost/correction comparison rules before candidate inference. Empty/absent denominators yield UNKNOWN, never zero error or a passing gate. Missing minimum coverage permits an engineering run but yields evaluation-incomplete and blocks quality/economy success and a positive scaling decision. Negative/rejection decisions remain possible. Unmeasured correction effort is UNKNOWN; no claim of reduced total human effort may follow. Report provider-cost comparisons separately from total cost when human/setup costs are unmeasured. The difficult-page gate can record an explicit engineering-only authorization with missing references, provided all engines, execution limits and missing scopes are pinned before inference; its quality/economy verdict stays evaluation-incomplete. The later six-page gate likewise distinguishes approved assessment from explicitly authorized engineering-only execution. Neither mode bypasses owner configuration approval or creates missing judgments. No reference is fabricated by this proposal revision.

## Risks and trade-offs

Region-first recognition can lose context; region crops must retain declared padding/context and structural checks can revisit neighbors. Iteration can oscillate; canonical-state detection and hard limits terminate it. AI may invent plausible text; preserve image anchors, disagreements and uncertainty rather than treating model confidence as truth. Pinning remote model names cannot ensure fresh determinism; recorded replay provides the stronger reproducibility guarantee.

## Deferred decisions

Select engines, models, numerical budgets and quality thresholds in the pinned pilot manifest before execution. Production-scale issue processing, a general editor and demonstrated cross-tool conformance are outside this proposal.
